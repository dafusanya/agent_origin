# 🚀 本地金融安全情报 Agent 搭建全记录

> [!success] 核心里程碑
> 成功利用 LM Studio + Qwen/DeepSeek 本地模型，通过 Python 手写 Agent 循环，调用 `world-intel-mcp` 的 132 个工具，实现了从真实互联网抓取安全情报（如 QakBot）并生成结构化简报的完整闭环。

## 🎯 项目背景与目标
- **背景**：作为电子信息工程（信息安全）+ 金融辅修的学生，需要探索 AI 在安全领域的实战应用。
- **目标**：利用手头的 32G 内存笔记本和 Burp Suite Pro，在**零云端 API 成本**的前提下，搭建一个能自动抓取全球 OSINT 情报、且能够用大模型进行金融安全威胁分析的本地 Agent。

## 🛠️ 技术栈 (Tech Stack)
- **LLM 本地运行时**：[[LM Studio]] (v0.4.26)
- **核心模型**：[[Qwen2.5-Coder-7B-Instruct]] / [[DeepSeek-R1-0528-Qwen3-8B]]

## 🐛 踩坑与排错记录 (Debugging Log)

> [!bug] 环境报错：`error: externally-managed-environment`
> **原因**：在系统全局 Python 或 MSYS2 环境中直接 `pip install`，触发了 PEP 668 保护机制。
> **解决**：严格使用 `E:\venv\Scripts\python.exe` 创建隔离的虚拟环境，并在 PyCharm 中绑定该解释器。

> [!bug] 路径冲突：`MCP error -32000: Connection closed`
> **原因**：项目路径嵌套过深，且 `mcp.json` 中直接调用 `.exe` 时错误地添加了 `-m` 参数导致段错误；此外 PyCharm 后台进程与 LM Studio 抢夺进程。
> **解决**：将 `venv` 抽离至 `E:\venv` 缩短路径。`mcp.json` 改用 `python.exe -m world_intel_mcp` 或直接指向 `world-intel-mcp.exe` 并清空 `args`，同时配置 `"PYTHONIOENCODING": "utf-8"`。

> [!bug] 模型幻觉：LM Studio 界面下的“演戏式”回答
> **原因**：8B 模型在 LM Studio 界面中，未能正确挂载 132 个工具（信息过载），且模型自己脑补了 `web_search` 工具，甚至伪造了 `https://example.com` 的假链接。
> **解决**：放弃在 UI 界面死磕。即使尝试精简工具，依然受限于 UI 的兼容性。

> [!bug] API 限制：`URL resolves to a non-public address`
> **原因**：尝试通过 Python 请求 LM Studio API，并动态传入 `http://localhost:1234/mcp/...`。出于防 SSRF 攻击的安全策略，LM Studio 拒绝动态连接本地地址。
> **解决**：放弃动态传入 `integrations`，改为**手写 Python Agent 循环**。
